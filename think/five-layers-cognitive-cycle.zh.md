# Martech AI 五层：决策与学习循环

*[English version](five-layers-cognitive-cycle.md)*

核查日期：2026-09-30。五层是一种有用的功能分解，不是唯一的产业分类。一个产品、服务或团队可以承担多个职责。只在有助于问责和诊断时拆分，不应为了图示建立五套服务。

目标是在预算、同意状态、履约能力和客户体验约束下，选择并执行创造长期增量价值的行动，再用证据更新决策。

| 职责 | 问题 | 产物 | 简称 |
|---|---|---|---|
| Data | 观察、推断和记录了什么？ | 事件、身份关联、同意与来源 | 记录 |
| Intelligence | 能估计哪些结果或干预效果？ | 分数、向量、效果估计与不确定性 | 信念 |
| Decision | 应选择哪个合格动作？ | 带约束与理由的行动或不行动 | 选择 |
| Activation | 能否正确执行获授权的动作？ | 送达、失败与实际曝光记录 | 行动 |
| Measurement | 哪些假设下，证据支持什么？ | 估计、区间、诊断与学习 | 证据 |

## 1. Data：保留来源的记录

负责事件定义、身份解析、时间戳、同意与删除状态。购买记录、概率身份匹配与购买倾向预测的证据性质不同，即使存于同一仓库。保留来源、观察或推断类型、方法与版本、有意义的置信度、有效时间和允许用途。身份匹配概率不是同一人的证明。

重复转化、时区错位、曝光日志缺失、退款延迟与同意状态不一致都是数据故障。先与业务系统对账，再判断模型是否有问题。

## 2. Intelligence：定义清楚的估计目标

预测估计既有策略产生的数据中的结果；因果模型在识别假设下估计干预差异。高购买概率不代表高干预效果。记录人群、时间范围、处理定义与训练策略。

RL 跨越两层：策略学习属于 Intelligence，受实时约束的策略应用属于 Decision。验证分布变化。选择性触达产生的历史日志不能自动识别未触达人群或未尝试动作的结果。

## 3. Decision：受约束的选择

选择受众、出价、优惠、时机、渠道或不触达。先建立透明规则基线。比较扣除折扣、退款、履约与营销成本后的增量贡献；归因收入可能偏好不盈利的活动。

历史平均回报与追加预算的回报不同。扩量需要局部实验或有依据的响应曲线，并明确有效范围。证据不足时可以再实验，也可以记录受控风险的经营选择，但不能把提案写成已证明结论。

## 4. Activation：行动契约

执行时检查资格、同意、频控、库存、优惠有效性和支出限制。定义权限、幂等键、重试、取消、回滚与转人工。记录提议、批准、实际曝光、失败原因与策略版本。执行成功与业务成功分别度量。

同一平台可以同时负责选择与执行。对话中也可能发生新决策，因此不一定只是被动通道。

## 5. Measurement：证据与不确定性

实验、观察性因果方法、MMM 和归因提供不同证据。归因按规则或模型分配功劳，本身不能识别增量。MMM 的因果解释需要假设、有效变化、混杂控制与敏感性分析。[Meridian 介绍](https://developers.google.com/meridian/docs/basics/meridian-introduction)说明了后验不确定性与响应曲线。

确认性实验运行前定义估计目标、随机化单元、观察窗口、结果成熟期、排除规则、业务门槛和护栏。按分配单元分析，处理干扰、聚类和残留效应。参见 [Switchback 实验设计与分析](https://arxiv.org/abs/2009.00148)。

固定窗口实验不能在普通 p 值首次达标时宣布成功。运行安全监控与效果证明分开。同时报告点估计、区间、缺失与诊断。p 值不是假设为真的概率，`1 − p` 不是可信度；正向效果也可能未达到业务要求。参见 [ASA 声明](https://www.amstat.org/asa/files/pdfs/P-ValueStatement.pdf)。

## 边界与反馈

```text
Data → Intelligence → Decision → Activation → Measurement
  ↑                                  │           │
  └──────── 观察结果与行动日志 ──────────┘           │
  └──────────── 实验记录 ──────────────────────────┘
          Intelligence ← 证据与不确定性
```

| 边界 | 工程要求 |
|---|---|
| 记录 / 推断 | 存储中保留来源与不确定性。 |
| 预测 / 选择 | 结合成本、因果相关性与约束。 |
| 选择 / 执行 | 分别诊断策略故障与送达故障。 |
| 执行 / 证据 | 用反事实评价已执行行动。 |

记录资格、分配概率和曝光，使后续分析可以理解选择过程。探索需要评估设计与权限。反复回灌被旧策略选择过的结果，不保证正确的因果学习。

平台与治理支撑全部职责。Agent 和工作流编排工作，但不会自动提供反事实。缺少因果测量的系统可以运行，只是宣称增量价值的依据受到限制。
