# 营销 Agent 的四种典型形态

*[English version](marketing-agent-classes.md)*

核查日期：2026-09-30。保留原来的四种类别作为**可交叉的典型运营形态**，说明系统在哪里工作、与谁形成客户关系，以及能控制哪些行动。平台权属、操作范围、交互方式和发现渠道属于不同维度。生命周期产品可以同时独立、对话式和主动触达。位置本身不能推出技术架构、成熟度或盈利能力。

## 四种形态的运营逻辑

| 形态 | 工作位置 | 典型客户 | 行动控制与工作流 | 需要核实的商业模式 |
|---|---|---|---|---|
| 1 — 平台内置 | 广告购买界面内部 | 广告主 | 信号 → 出价、受众、创意 → 投放与反馈 | 与广告支出相关的平台收入；具体库存关系不同 |
| 2 — 独立跨渠道 | 外部账户与渠道之间 | 品牌或代理商 | 业务目标 → 跨渠道计划 → API 动作与审批 → 评价 | SaaS、服务费或支出相关费用 |
| 3 — 对话与服务 | 客户对话及后续跟进 | 客服、销售或生命周期团队 | 意图与上下文 → 对话和工具动作 → 解决、转人工或跟进 | 席位、用量、解决量或企业合同 |
| 4 — Agent 中介发现 | AI 回答、界面或商业路径 | 品牌或商业团队 | 可见度、内容或获授权商业动作 → 对应渠道评价 | 取决于产品的订阅、服务或其他模式 |

这四种形态是实用的分析入口，不能画成统一二维分类中互斥的四个象限。DSP 可以同时控制购买界面并提供独立编排；客户 Agent 可以同时对话并执行跨渠道生命周期行动。行业对“Agent”的使用范围较宽，平台优化器不自动等于 LLM Agent。

## 用独立维度描述系统

| 维度 | 应记录的问题 |
|---|---|
| 客户 | 谁付钱、谁使用、优化谁的利益？ |
| 任务 | 获客、创意、激活、留存、服务、销售或发现？ |
| 数据访问 | 平台信号、第一方记录、公开内容或组合？ |
| 行动控制 | 库存、出价、消息、优惠或交易；哪些渠道？ |
| 技术机制 | 规则、预测 ML、因果模型、优化、固定工作流、LLM Agent 或混合？ |
| 自主权限 | 建议、起草、执行获批准动作或受限自主运行？ |
| 证据与成熟度 | 披露了什么、日期、基线与限制是什么？ |

以具体产品和工作流为单位，不把多业务集团强行放入一格。未披露的架构保持未知。[Anthropic 工程文章](https://www.anthropic.com/engineering/building-effective-agents)区分预设流程与由模型动态决定过程和工具的 Agent；自主优化本身不证明 LLM Agent 机制。

## 形态 1：平台内置自动化

平台可以在购买界面内部决定出价、节奏、受众或创意。区分**自有用户注意力**与**聚合第三方供给**，并记录混合业务。

- Google、Meta、Amazon 和 TikTok 广告具有平台内自动化。
- 腾讯自有微信等流量、阿里自有电商流量属于自有注意力子类；外部联盟业务需另记。
- AppLovin、Mintegral、Criteo 提供网络或供给聚合参考，应注明具体产品和供给关系。
- Moloco 提供 ML 购买与零售媒体基础设施。The Trade Desk 是独立 DSP，控制购买而不拥有 publisher 注意力，也可从形态 2 分析。

库存、拍卖信号和送达控制可能形成优势，不能据此排名谁最赚钱。广告流水、净收入、流量分成与获客成本的会计口径不同。

## 形态 2：独立跨渠道 Agent

外部产品连接广告账户、第一方结果、创意与审批。Albert.ai、Ryze AI、Jellyfish、Muze AI、Uplane 是产品参考；公开定位不证明具体架构或普遍增量。

[Lapis 的 YC 页面](https://www.ycombinator.com/companies/lapis)目前描述广告创建和运营，早期发布文本描述 AI 搜索分析。这些是有日期的定位信息，不能证明 ChatGPT 内原生广告投放。产品范围会变化。

实际竞争问题是：**相比渠道内自动化，多提供了什么决策、数据或执行能力？**利润目标、跨渠道频控、退款、履约约束与实验是候选价值点，应对照简单基线验证。

## 形态 3：对话与服务 Agent

服务、销售、续费和召回结合对话与长期决策，可能入站、出站或兼有。“点击后”过窄。

[Sierra Horizon](https://sierra.ai/blog/horizon)于 2026-07-16 发布，描述跨天或跨月的主动交互。这是功能范围的供应商证据，不是增量留存或收入的独立证明。Decagon、Intercom Fin、Cresta、Ada、Cognigy、Parloa 提供其他参考。

服务解决与营销价值交叉但不相同。同时评价事实、任务、权限、转人工，以及增量有效销售、留存或贡献，纳入投诉、退订和退款。按解决量收费是商业单位，不是因果效果指标。

## 形态 4：Agent 中介的发现与商业

| 机制 | 评价对象 | 不能自动证明 |
|---|---|---|
| GEO / AEO | 生成回答中的可见度与引用 | 增量购买或稳定排名 |
| AI 界面广告 | 通常展示给人的付费广告 | Agent 本身成为受众 |
| Agent 辅助购买 | 获授权购物或交易 | 买卖双方 Agent 协商 |
| Agent-to-Agent | Agent 间结构化交换 | 权限、经济价值或因果有效性 |

Profound、Daydream、Scrunch 是发现相关参考。[Sitefire 的 YC 页面](https://www.ycombinator.com/companies/sitefire)描述可见度分析、内容和 CMS 动作，应归于发现优化而非付费广告位。定义查询分布、重复采样、模型版本，并验证下游业务结果。

渠道变化可能改变营销工作；变化的幅度、时间与搜索替代仍需验证。本清单缺少披露不能证明整个类别没有商业规模。

## 横跨形态的第一方生命周期决策

生命周期决策涉及激活、留存、续费与召回，可以通过对话、消息、优惠或不触达来实现，不局限于对话服务。

[BrazeAI Decisioning Studio](https://www.braze.com/product/brazeai-decisioning-studio)公开描述第一方数据、自定义 KPI、渠道、优惠、频次与约束，跨越 Intelligence、Decision、Activation、Measurement，也可与形态 2 和 3 交叉。应评价资格检查 → 行动选择 → 获授权送达 → 成熟结果 → 增量学习，并包含不触达基线与负面反馈。

[Hightouch AI Decisioning 文档](https://hightouch.com/docs/ai-decisioning/overview)同样描述基于强化学习的消息、渠道、时机选择和关联送达。产品使用 Agent 名称，不证明 LLM 动态规划或因果增量。核查日期：2026-09-30。

## 经济分析不依赖类别排名

流量利润、SaaS、服务费、结果计价、支出抽成可以并存。在指定时期比较收入确认、毛利、营业利润、扣除服务成本的贡献、客户集中度与留存。管理广告费不是收入，ARR 不隔离 LLM 推理的价值，缺反事实的客户案例不证明增量。

网络效应与信号同址是候选优势，也受 publisher 依赖、平台接口变化、拍卖竞争、获客与合规成本影响。判断哪个控制点创造持续价值，并检查证据。

## 中国与美国生态比较

比较具体供给平面、账户权限、第一方数据、集成成本与客户需求。腾讯、阿里、字节经营主要自有渠道；Mintegral 聚合外部供给。“独立编排在中国空间更小”需要市场和客户证据，不能仅由大平台占优推出。

## 如何验证 LLM 的价值

商业语境策略、创意迭代、工具化客户工作与信息解释是可测试机会。对照固定工作流和人工基线，比较正确性、成本、延迟、权限与增量业务结果。高频竞价应与现有优化器实测比较，而不预设技术胜负。

第一方访问与执行权限取决于产品，生命周期系统已具有这些能力。不能把融合描述成全行业尚未发生的未来事件。建立明确系统档案，验证贡献，并随功能范围变化复核。
